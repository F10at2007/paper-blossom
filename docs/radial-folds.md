# 三折、六折团花实现与验收

日期：2026-10-23。本次未引入依赖，未实现五折。

## 实现

先完成三折并在 Chrome 129 通过 16 项浏览器检查，然后接入六折。最终两种团花联合检查 46 项通过。

- 三折 `radial3`：60° 基础扇区；原路径与镜像组成 120° 单元，再以 120° 间隔旋转，形成三向对称、六个扇区。
- 六折 `radial6`：30° 基础扇区；原路径与镜像组成 60° 单元，再以 60° 间隔旋转，形成六向对称、十二个扇区。
- 中心沿用 (0.5, 0.5)，旋转和镜像均为等距变换。镜像顶点顺序沿用原有处理。变换不修改基础路径、不新增历史。
- 新团花采用内接圆形外缘；统一正 360 边形定义纸张和扇区，2048 像素下与圆的最大偏差约 0.04 像素。旧折法继续使用原始方纸。
- 纸片居中展示，保留纸外起笔；提交时使用现有凸多边形裁剪。点击展开才呈现最终作品并启用下载。
- 真实透明镂空仍使用 renderPaper 的 destination-out，圆形外缘由 fold-render 的 destination-in 遮罩处理。编辑辅助线不进入纸张层。
- 工作台、保存缩略图、作品库下载及 PNG 共用 renderFoldPaper；下载器、撤销重做、保存格式和现有校验均复用。

折叠说明采用经用户认可的几何化方案：三折对应先对折并定位原纸中心，再将半周分三份叠合；六折在该扇区基础上再对半折。软件不模拟真实纸张的层叠厚度或方纸折后参差外缘，也不把该描述宣称为所有传统流派的统一命名标准。三向/六向是重复方向，不能理解为固定花瓣数。

## 验证边界与既有问题

原 `composition reload restores exact arrangement bitmap` 失败现已定位并修复测试：频繁读取交互画布触发 Canvas 渲染后端变化，半透明边缘栅格化不同，严格字符串断言将其误判为恢复异常。保存恢复的数据没有变化；不是团花扩展引入的业务缺陷。

正式测试现固定拼接严格位图测试的上下文条件，逐通道零容差比较解码像素；另外保留默认上下文的真实交互、保存恢复和 PNG 导出验收。恢复后再次保存实际编辑模型，严格比较元素 ID、顺序、位置、大小、角度及颜色。完整四模式回归 74 项全部通过（64 项主流程、10 项默认拼接专项），无排除项；业务保存恢复和渲染代码未改。详细原因、修复与最新证据见 [位图恢复测试验收](composition-rendering-tests.md)。

上述触控验证为 Chrome CDP 输入，不代表实体手机手工验收。尚未做大量极长路径压力测试。抗锯齿边缘允许栅格化差异，不承诺任意角度逐像素旋转完全一致。

测试服务器在 8001；默认 8000 如为旧的 --noreload 服务，需要重启后才能更新模板/页面说明。脚本仅应在独立测试浏览器配置执行。
