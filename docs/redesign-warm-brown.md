### `/modes/` 的四张卡为什么做成卷轴

模式选择页原本贴的是仓库自带的四个单色 SVG 纹样（`core/art/{flower,butterfly,sprig,tiles}.svg`），和首页那份卷轴视觉差一档，看着「太简略」。现在改成四条悬挂卷轴，全部由 CSS 画成，不引入任何图片库：

- 上下两根木杆：`linear-gradient` 三段色 + 细金线（`repeating-linear-gradient`）+ 两端 `::before/::after` 深木轴头；杆色按各自牌匾取，`--rod-hi/mid/lo` 四组分色写在 `.rod-fold / .rod-free / .rod-trace / .rod-compose` 上（褐红、赭橙、青蓝、竹青）；
- 中间纸面：暖纸渐变 + 横向纸纤维 + 外框金线内阴影，纸面里嵌的就是 Frame 5 卷轴上的那张纹样（`core/media/card-{symmetry,free,trace,compose}.webp`，都是 680×1104，含匾额与流苏）；
- 纸角有编号与朱印（朱印两字取自模式，如「对折」「随剪」），`modes.py` 为此新增 `art` / `seal` 两个字段；
- 下方文字块从原来的「和图片粘成一张卡」拆成独立的一截横向卷轴：左右两端各一根立轴（同一套 `--rod-*` 分色），中间是纸面，字体统一到整套的宋体层（`--serif`，标题 22px / 正文 12.5px / 行高 1.95）；
- 交互保留一个动作：hover 时整条卷轴轻抬 5px。

第一张卡「对称之美」的纹样在设计稿里本身是斜着摆的（匾额右高左低），直接裁下来会显得卡片歪。改成先用 ffmpeg 把整块区域 crop 出来、`rotate=-9°` 把卡面转正、再裁 700×1136 缩到 680×1104，和其余三张同尺寸；命令：

```
ffmpeg -i "图像优化 (1) 1.png" \
  -vf "crop=900:1270:330:1330,rotate=-9*PI/180:ow=iw:oh=ih:c=none,crop=700:1136:128:31,scale=680:1104:flags=lanczos" \
  -q:v 88 -f webp card-symmetry.webp
```

裁切时留了设计稿原有的金色边框与流苏，因此转正后卡面仍完整，不会出现斜切的边。

首页首屏那张卡的热区悬停图层仍用未旋转的版本 `card-symmetry-flat.webp`（按原坐标 `crop=665:1080:430:1425` 重出），因为悬停图是叠在设计稿原位上做「抬起」效果的，一旦换成转正版就会和底下的斜卡对不上，所以两张图分工：`/modes/` 用摆正版，首页悬停用原位版。

### 首页悬停：按金框裁下来的「挂屏」而不是整块矩形

原来 hover 是把整块 680×1104 的矩形卡连底纸一起放大，看着像贴片。现在每个热区里叠两层图：底层 `card-*.webp` 始终透明（只占位），上层 `card-*-pop.webp` 是**沿纹样外面那圈金色外框裁下来的透明件**，只有 hover/focus 时才淡入并放大。

裁切件的做法（`.qa/hex-auto4.mjs` 取形状 + `.qa/stencil.mjs` 逐卡套用，中间产物在 `D:\web\UI\_preview\hex\`）：

- 自动抠框的几条路都不成立：亮纸泛洪、边缘感知泛洪取最大连通块（抓到的是纹样本身）、按明度逐行扫描框线（纸纹与画布边上的零碎金饰都会误触发）。根本原因是金框是一圈**会断的线**，断口位置每张卡都不同，泛洪会从断口漏进去或把框外的纸带回来；
- 现在的做法：只取「金框那一圈」的像素（`r−b>116` 或 `lum<176`，限定在匾额窗口内，再取跨度最大的连通块），闭运算接断口后按 900 个角度取最远半径做径向剖面，中位滤波去单角度突起，得到一条**贴合金框外缘的轮廓**；
- 四张匾额是同一套稿，所以轮廓只需算一次（用第一张），其余三张按各自「金饰外接框」的比例平移对齐后套用，再用遮罩内收 4px，让切口正好落在金线外侧；
- 匾额比金框还宽，直接按框裁会把匾额两端切掉，因此遮罩之外再并一条匾额横带（含中国结）进 alpha；
- 底边只对中轴那一条（流苏）做纵向 alpha 渐隐（`fadeY` 起、`bottomY` 止），框本身的 V 形底边保持硬边——两层图同源，渐隐区看不出接缝；
- 最后 5px 方框模糊做 2px 级抗锯齿。

样式上 `.hotspot > img.pop` 用 `precision` 以外的东西补齐了原来的矩形感：`drop-shadow` 按透明轮廓投影（不是 box-shadow），外加一层 1px 暖白描边模拟纸边反光；原来那条 `mask-image: radial-gradient(...)` 已经删掉，因为它会把裁好的四角再啃掉一圈。`prefers-reduced-motion` 下只保留淡入、不做位移缩放。

## 二、样式分层

CSS 的加载顺序是刻意设计的，改动前请先读这一条：

```
site.css        →  基础排版与仓库自带的页面样式
{% block extra_head %}  →  各工坊页自己的样式（fold/free/final-workshop.css）
warm.css        →  本次改版的整体视觉层，必须最后加载
```

`warm.css` 只能覆盖，不能反过来被页面级样式压住，否则会出现「折纸页步骤条错位、按钮变透明、纸张被压小」这类问题。

同时有一条反向约束：`warm.css` 的选择器权重不能高过仓库里已有的功能态规则。典型例子是「放大画布」：

```css
/* 仓库自带，final-workshop.css */
.workspace.is-focused { grid-template-columns: minmax(0, 1fr) 230px; }
```

如果 `warm.css` 里写成 `.workshop-page .workspace`（权重 0,2,0 与前者相同、但更靠后），就会把聚焦布局压掉，纸张被挤到 144px。写成单个 `.workspace`（0,1,0）才让功能态规则正常生效。同理，`background` 简写会清掉 `.checkerboard` 的 `background-image`，铺纸色只能用 `background-color`。

## 三、色面与底部色带

设计稿的纸面不是奶油黄。采样 Frame 1 / Frame 2 得到的实际值是 `#FDFAF4`（页面与画布块底）、`#FCF9F4`（侧栏顶部）、`#AC8D7F` 与 `#AB8080`（底部色带）。此前用的 `#FDF7EC / #FFF0D5 / #F7E2C4` 一组奶油色比设计稿明显偏黄，已整体替换：

| 位置 | 旧值 | 现值 |
| --- | --- | --- |
| `--cream` | `#FDF7EC` | `#FDFAF4` |
| `--paper` / `--paper-2` | `#FDF2DF` / `#F8E5C8` | `#FBF6EC` / `#F3E9DA` |
| 画布块 `.canvas-panel` | `#FFFDF8` | `#FDFAF4` |
| 画布底 `.canvas-area` | 米色点阵 | `#FDFAF4` 纯色 |
| 顶部信息条 `.canvas-top`、快捷键条、折纸步骤条 | 各自的奶油渐变 | 统一 `#FDFAF4` |
| 模式卡 / 折叠卡 / 次级按钮 | `#FFF9EC` 系 | `rgba(253,250,244,.95~.97)` |

要再调色只改 `warm.css` 顶部的 `:root` 变量，不要在页面级样式里另写死颜色——`extra_head` 的样式先于 `warm.css` 加载，写在那儿会被覆盖。

### 底部那条色带

设计稿里白色画布块不贴底，下面是一条横贯整页的暖色虚化带。这件事要四段配合，缺一段就会「颜色割裂」——只贴一条色带、两侧栏却淡成奶油白，就会出现三段互不相连的色面：

1. `.workspace` 打一张 `workshop-bg.webp` 作为整页共用的实景底。它由左右两栏底部各 1100px 切出、横向拼合、`gblur sigma=140` 融掉接缝，1600×1100、4.6KB；
2. 左右两栏的蒙层到底部淡到完全透明（`rgba(253,250,244,0)`），照片透出来，三栏才落回同一张底；
3. `.workspace::after` 把同学给的「图像优化 3」（`panel-fade.webp`，2816×124）压在整行最底部 34–58px，用 `mask-image` 从透明渐显，把三栏收成同一个色面；
4. `.canvas-panel` 留 `margin-bottom: clamp(38px, 4.4vw, 66px)`，白色画布块因此不贴底，色带露出。窄屏（≤900px）改单栏，`margin-bottom` 归零、`.workspace` 底部补 44px 内边距，色带落在页脚之前。

`workshop-bg.webp` 本身是模糊图，`background-size: 100% 100%` 直接拉伸即可，不必再出多档。

### 首页首屏不做虚化延展

首屏按理说铺满视口最省事，但 4066×2640 的图塞进 16:9 就只能靠虚化背景补边，补出来的那条边和照片本身的色调接不上，看起来是「上下各贴了一条」。现在改成：

- `.stage` 宽度 100%、`aspect-ratio: 4066/2640`，按原比例铺满宽度，不裁不拉伸；1920 宽时高约 1246px，比一屏高一点，页面自然往下滚；
- `.hero-stage` 不再引用 `bg-gutter.webp`（那张虚化延展图已停用），底色留 `#33160f` 兜底；
- 首屏外面没有任何过渡带，热区与标题都用百分比定位，跟着图一起缩放。

首页末尾的「关于工坊」（`home-note`）整块已删除，含右侧 01–04 列表与全部样式；首页顺序现在是：首屏舞台 → 向下引导 → 非遗剪纸卡片 → 页脚。

## 五、开场怎么接上首屏

1. **视频不铺满屏幕，而是铺满「首屏那张图」的同一个盒子**。`--head-h` 由 `intro-gate.js` 按 header 实测高度写进根元素，`.gate-inner` 用 `aspect-ratio: 4066 / 2640` 严丝合缝地压在 `.stage` 那个矩形上，视频 `object-fit: cover`。门厅里看到的画面因此和下面那张图是同一构图、同一位置，没有黑场、没有留边、没有第二个边框。
2. **播完就自动接上，不存在「手动结束」**。`ended` → 0.9s 淡出 → 隐藏。另外三条兜底，避免任何情况下都要人点一下：`play()` 被浏览器拒绝时 2.6s 自动收场、`error` 立即收场、`loadedmetadata` 之后按片长 +1.6s 强收场（防系统休眠导致 `ended` 不触发）。
3. **静音自动播放 + 「开启声音」按钮**。浏览器禁止带声自动播放。
4. **2 秒后浮现「跳过开场」**，`sessionStorage` 记住已看过，同一次会话只播一次；右上角保留「重看开场」；`?intro=0` 强制跳过，方便答辩演示。
5. 代价说清楚：视频是 960×720，铺到 1920 宽是 2 倍放大，会比首屏那张静态图软一些；视频取景比首屏图紧约 1.27 倍，所以交接那一下是一次很轻的「拉远」，不是逐像素重合。要逐像素重合只能把首屏裁成 4:3，那等于改版式，所以没做。

## 六、非遗内容的取舍

评审细则里「内容充实度」的档位是「白板 1 / 复读机 2 / 图文并茂 3 / 真实网站 4 / 丰富多彩 5」。首页放一百字简介只能到 3 分，因此做成两层：

- 首页 `heritage-band`：圆图 + 一句主张 + 两段短文 + 两个入口；
- 独立内容页 `/heritage/`：七章长文（源流、技法、造型语言、纹样寓意、地域流派、当代传承、资料来源），含「千刻不落，万剪不断」的引文、剪刻撕烫衬点六格、阳刻与阴刻及纸桥的说明、八条纹样寓意、六个地域流派卡片，并把 UNESCO 名录页与 `ihchina.cn` 作为可核查的外部来源。

文中不做无出处的考据断言，凡涉及年份与名录只引用可核查来源。
