# 折叠渲染计算与自由剪纸释放等待验收

日期：2026-11-10。未新增依赖、未改折法定义、保存格式、交互或 PNG 规格。

## 修改前基线（代码核对）

- `FoldSession.finalPaths` 对每条基础路径调用一次 `unfoldPaths`，而 `finalGroups` 又逐条调用一次；`renderFoldPaper` 同时读取两者。每次展开作品渲染造成基础点镜像/旋转两轮。
- `free-workshop.js` 给 downloader 预先求 `fold?.finalPaths`、`fold?.finalGroups`，同时传入折叠专用 renderer；`paper-download.js` 随即忽略这两个参数。
- 同一帧的 `drawGuide()` 对每个点调用 `toFoldView()`，而它每次重新执行相同 mode 的 `foldView()`。
- 剪裁状态工作台仍通过 `renderFoldedPaper()` 仅绘制居中的折后纸片；最终展开/导出路径在点击展开后才参与最终画布渲染。
- `paper-download.js` 在创建 Blob URL 后 10,000ms 释放。测试文件在本轮开始前已有未提交改动，把 `until()` 从 HEAD 的 100×50ms（约 5 秒）临时扩大到 300×50ms（约 15 秒）；这让本脚本所有等待都变长，但没有释放专用截止时间或逐 URL 诊断。本次保留其他轮询的原 300 次 / 50ms 默认轮询，只给释放断言设置独立 12 秒截止，并保留逐 URL 诊断。

## 同机几何基线与优化后结果

在同一隔离 Chrome 156.0.8078.80 页面、同一机器、同一 20,000 点非对称路径和 2048 × 2048 Canvas 上，逐模式先运行旧访问序列（`finalPaths` 后 `finalGroups`），再运行合并访问（`finalGeometry`）。旧/新计时各丢弃一次预热，报告剩余五次几何生成中位数；PNG 编码单独对已绘制的优化结果执行五次并取中位数。时长用于说明该机上的变化，不是性能门槛。

| 折法 | unfoldPaths 调用/基础路径（旧→新） | 生成映射点（旧→新） | 几何中位数 ms（旧→新） | PNG 编码中位数 ms | 解码位图 RGBA 通道差异 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 垂直 | 2 → 1 | 80,000 → 40,000 | 1.4 → 0.7 | 7.9 | 0 |
| 水平 | 2 → 1 | 80,000 → 40,000 | 1.3 → 0.6 | 8.1 | 0 |
| 四折 | 2 → 1 | 160,000 → 80,000 | 3.3 → 1.9 | 8.6 | 0 |
| 八折 | 2 → 1 | 320,000 → 160,000 | 6.2 → 3.1 | 9.5 | 0 |
| 三折团花 | 2 → 1 | 240,000 → 120,000 | 10.7 → 4.4 | 9.4 | 0 |
| 六折团花 | 2 → 1 | 480,000 → 240,000 | 16.1 → 9.5 | 20.0 | 0 |

“映射点”计入实际生成的各副本顶点；六折团花从 24 万个到 12 万个最终顶点。基准把旧/新结果分别编码为 PNG，再解码后在固定颜色、尺寸和外缘遮罩下逐 RGBA 通道零容差比较，六种折法均完全一致。PNG 编码时间独立计时，不与几何时间合并。基准记录保存在忽略目录 `.qa/fold-opt-benchmark.json`。

## 实现与专项验收

- `FoldSession.finalGeometry` 对每条基础刀痕只调用一轮展开，同时提供按刀分组数组和兼容平铺数组；路径对象由分组与平铺输出共同引用。渲染仍将同一刀的所有副本放在一个偶奇填充路径中，保留折痕接缝语义。
- `renderFoldPaper`、工作台展开画布、作品缩略图/保存恢复及作品库下载继续共用 `renderFoldPaper`。折叠剪裁态仍仅绘制居中的纸片；专用下载 renderer 的场景不再提前求值并丢弃 finalPaths/finalGroups。
- `drawGuide()` 每帧只计算一次 `foldView()` 并用于所有路径点。没有加跨帧缓存。
- 新增的几何单测检查平铺和分组结果一致且共享展开对象。
- 自由剪纸释放测试先断言两个 URL 均已创建，再按各自 URL 轮询释放；该项截止时间 12 秒，其他 `until()` 调用保留原 300 次 / 50ms 默认轮询。超时报告列出创建、释放和未释放地址。
